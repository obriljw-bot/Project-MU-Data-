# Auto Broadcasting Helper — 기능 개선 아이디어

---

## 오등록 코드 수정 UX 개선

### 배경 / 문제 상황

라이브 방송 중 제품 코드를 잘못 등록했을 때의 현재 수정 흐름:

1. Product Sales Info 에서 잘못된 제품 코드를 잘라내기 (code → `""`)
2. 올바른 제품에 붙여넣기
3. 기존 판매수량 수동 조정
4. 관련 판매 로그 수동 재처리

**문제점**: `selectedProductRef` stale 참조 + cut/paste 순서 실수 → 판매수량이 엉뚱한 제품에 적용되는 버그 발생 위험이 높음. 제품이 50개 이상이면 실수 가능성 더 증가.

---

### 채택 방향: 아이디어 2번 + 검색 모달 조합

> 제품 테이블에서 이미 문제 제품을 눈으로 확인한 상태에서 시작하므로,  
> **ProductTable 행에 "코드이동 →" 버튼** + **검색 가능한 대상 선택 모달** 조합이 최적.

#### 상세 흐름

```
ProductTable에서 잘못 등록된 제품 행 확인
  → [코드이동 →] 버튼 클릭
    → 모달 열림: "코드 'XXX'를 어느 제품으로 이동?"
      → 제품명/코드로 타이핑 검색 (2~3자 입력으로 50개 중 필터)
        → 대상 제품 선택
          → 옵션 체크박스:
              ☑ 관련 판매 로그도 이동 (N개)
              ☑ 기존 제품 판매수량 0으로 초기화
          → [이동] 클릭
            → 원자적 처리: 코드 이동 + 로그 재처리 + 수량 정산
```

#### 구현 시 핵심 포인트

- **원자적 상태 업데이트**: `setProducts` 한 번 호출로 소스/타겟 동시 변경 (stale ref 회피)
- **검색 모달**: 제품명 + 코드 동시 검색, 키보드 입력 즉시 필터
- **로그 재처리**: 이동 대상 코드의 `applied: false` 로그 → 타겟 제품에 적용, `applied: true` 로그 → 소스 차감 / 타겟 가산 선택 가능
- **수량 초기화 옵션**: 소스 제품 `sales: 0` 리셋 여부 사용자 선택

### 참고: 검토했던 다른 아이디어들

| 아이디어 | 장점 | 단점 |
|---|---|---|
| **1번** 판매 로그에서 직접 제품 변경 | 로그 레벨 재배정으로 구조적으로 안전 | 50개+ 드롭다운 → 라이브 중 선택 어려움 |
| **2번** ProductTable "코드이동 →" 버튼 | 문제 제품 행에서 바로 시작, 직관적 | 검색 모달 구현 필요 (단순 드롭다운 불가) |
| **3번** 코드 변경 시 자동 팝업 제안 | 기존 편집 방식 유지, 구현 비용 최소 | 변경 감지 타이밍에 따라 팝업 혼란 가능 |
| **4번** 판매수량 ±버튼으로 조정 로그 생성 | 수동 조정 내역 추적 가능 | 코드 오등록 문제 자체를 해결하지 않음 |

## 기타 메모

- 현재 적용된 임시 버그픽스: `handleMapNewCode` 코드 충돌 차단, `handleUpdateProduct` stale ref 즉시 동기화, `selectedProduct` useEffect 자동 최신화 (`App.jsx`)
- 위 아이디어 구현 시 임시 버그픽스 일부는 제거해도 됨 (구조적으로 해결되므로)
